# otelcol-config-schemas

Component schemas for OpenTelemetry Collector releases, one file per release
**per distribution**. This is a data repository: it holds no code and is meant
to be read over HTTP.

```
index.json                     what this registry can serve
contrib/v0.157.0.{yaml,json}   the components otelcol-contrib ships
core/…                         plain otelcol
k8s/…                          otelcol-k8s
otlp/…                         otelcol-otlp
```

## Using it

[`otelcol-config-lint`](https://github.com/minuk-dev/otelcol-config-lint) reads
this registry by default. Point it elsewhere, or at a checkout of this
repository, with `--schema-location`:

```sh
otelcol-config-lint run --schema-location \
  https://raw.githubusercontent.com/minuk-dev/otelcol-config-schemas/main \
  config.yaml

otelcol-config-lint run --schema-location ./otelcol-config-schemas config.yaml
```

`--distribution` selects which of the directories above is read, so a config is
checked against the binary it will actually run on rather than against every
component that exists upstream.

## What a schema contains

Each file lists the components that release ships: the signals they support,
their per-signal stability, the settings they accept, and their Go module.

```yaml
collectorVersion: v0.157.0
distribution: core
components:
  receiver:
    otlp:
      type: otlp
      signals: [traces, metrics, logs, profiles]
      stability:
        traces: stable
      module: go.opentelemetry.io/collector/receiver/otlpreceiver
      fields:
        type: map
        children:
          protocols: {type: map, children: {...}}
```

The distribution is recorded once, at the top. Components carry no membership of
their own: the directory already answers that.

**Every file stands on its own.** Field schemas are resolved and inlined when
they are generated, so nothing here carries a `$ref` or needs a second file to
be read. What cannot be resolved — a third-party config such as Prometheus's
own, or a reference cycle in the stanza operators — is left `open`, so its keys
go unchecked rather than being reported as unknown.

`index.json` lists the releases each distribution has a schema for. Coverage
differs between them: upstream had no `otlp` distribution before v0.120.0.

## Generation

These files are generated by `tools/schemagen` in the linter repository, from
the upstream `metadata.yaml`, each component's `Config` struct, and the
`config.schema.yaml` upstream publishes from v0.150.0 on.

**Do not edit them by hand.**
